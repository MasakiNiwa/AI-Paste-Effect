# AI Paste Effect 仕様書

## 1. コンセプト

「エフェクトエディタ」ではなく **「AI 演出実行アプリ」**。

| 役割 | 担当 |
| --- | --- |
| 雰囲気・意図を伝える | ユーザー |
| 画像を見て演出プランを JSON で設計 | 普段使いの AI（ChatGPT / Gemini / Claude など） |
| JSON を安全に解釈して画像に描画 | このアプリ |
| 結果を見て AI にフィードバック | ユーザー |

### 守る制約

- **画像そのものは描き変えない。** 色・光・粒子・線・質感・ぼかしなどの演出のみ
- ユーザーにエフェクトの選択・数値調整をさせない（ホーム画面にスライダー等を置かない）
- 画像は端末外に送信しない（処理はすべてブラウザ内）

## 2. 画面

| 画面 | 内容 |
| --- | --- |
| 作成（ホーム） | ① プロンプトをコピー（適用後は「修正依頼をコピー」も）② AI の返答を貼り付け ③ 画像を読み込む。PC では右側に結果を表示 |
| 結果 | 結果の表示と元画像との比較（長押し / スライダー）、保存（PNG / JPEG / WebP）、共有。スマホでは下部ナビの独立したタブ |
| 共通 | 画面上部の「クリア」で JSON と画像を消して新しく始められる |
| 設定 | テーマ / 処理解像度 / 保存形式 / 自動適用 / 修正依頼に仕様を含める / JSON の保存 |
| ヘルプ | 使い方・コツ・できること・エフェクト一覧・バージョン情報・GitHub リンク |

ルーティングは GitHub Pages で動かすため HashRouter（`#/result`, `#/settings`, `#/help`）。
スマホ（lg 未満）は画面下部のタブバー（作成・結果・設定・ヘルプ）、PC は上部ナビ。

## 3. 演出プラン JSON（format: `ai-paste-effect`, version: 1）

```
plan
 ├─ format / version
 ├─ title / intent           … 演出の名前と狙い（表示用）
 ├─ analysis                  … AI の画像観察メモ（自由形式・描画には使わない）
 ├─ protect: Region[]         … 顔など、全レイヤーで効きを弱める領域
 └─ blocks[]                  … 演出の意味単位（上から順に重なる）
      ├─ id / purpose / enabled
      ├─ region / opacity     … 配下レイヤーの既定値
      └─ layers[]
           ├─ effect          … エフェクト ID
           ├─ params          … エフェクト固有パラメータ（省略分は既定値）
           ├─ opacity / blend
           ├─ region          … 省略時はブロックの region → 全体
           ├─ protect         … false で protect 領域にも効かせる
           └─ seed / enabled
```

簡略形として、`blocks` の代わりにトップレベルの `layers` 配列も受け付ける。

### 座標・単位

- 座標は正規化（左上 0,0 / 右下 1,1）。画面外も可
- サイズは「短辺比」（画像の短辺 = 1）
- 角度は度（0 = 右, 90 = 下）

### 領域 Region

`full` / `ellipse`（`circle`）/ `rect` / `linear` / `polygon` と、省略形の文字列 `full` `top` `bottom` `left` `right` `center` `edges`。
共通で `strength`（0〜1）と `invert` を持つ。配列は和集合、`protect` は除外として掛け算される。

### 寛容な解釈

AI の返答は揺れる前提で、失敗より警告を優先する。

- 前後の文章やコードフェンスを無視して最初の `{ … }` を抽出
- `JSON.parse` に失敗したら JSON5（末尾カンマ・コメント・シングルクォート）で再挑戦
- 範囲外の数値は丸め、型違いは既定値、未知のエフェクト／キーは無視 → いずれも警告
- 警告は「修正依頼をコピー」に自動で添付され、AI に直してもらえる

## 4. アーキテクチャ

```
src/
├─ engine/               描画エンジン（UI から独立）
│  ├─ params.ts          パラメータ宣言ヘルパー（型・範囲・既定値・説明）と正規化
│  ├─ region.ts          領域の正規化とマスク生成（純粋な数値計算）
│  ├─ plan.ts            JSON の抽出・正規化・ブロック→描画レイヤーへの平坦化
│  ├─ renderer.ts        描画パイプライン（PixiJS フィルタ + Canvas 2D 合成）
│  ├─ prompt.ts          AI 向けプロンプト生成（エフェクト登録簿から自動生成）
│  ├─ example.ts         記入例 / サンプル
│  └─ effects/           エフェクト定義（カテゴリ別）と登録簿 index.ts
├─ pages/                ホーム・設定・ヘルプ
├─ components/           レイアウト・UI 部品・トースト
├─ store/                Zustand（設定は localStorage に永続化）
└─ lib/                  クリップボード・画像入出力・バージョン情報
```

### エフェクト = 単一の情報源

各エフェクトは `defineEffect({ id, label, category, description, kind, defaultBlend, params, render })` で定義する。
この 1 つの定義から **AI 向けプロンプトの仕様書・ヘルプの一覧・JSON の正規化** がすべて生成されるので、
エフェクトの追加は「定義を書いて `effects/index.ts` に登録する」だけで完結する。

### 描画パイプライン

1. 画像を処理解像度（既定 2048px）に縮小
2. レイヤーごとに
   - エフェクトが画像と同サイズのキャンバスを描く（`filter` 型は現在の画像を加工、`overlay` 型は新規描画）
   - 領域マスク（region ∪, protect で除外）を `destination-in` で適用
   - `globalAlpha` と `globalCompositeOperation`（ブレンドモード）で重ねる
3. 粒子系はマスクに比例した確率で配置される
4. 乱数は seed 付きで、同じ JSON なら同じ結果になる

PixiJS / pixi-filters は初回描画時に遅延読み込みする。フィルタは端の欠けを防ぐため周囲に余白を足して掛け、WebGL 操作は直列化している。

### 使用ライブラリ

| 用途 | ライブラリ |
| --- | --- |
| ビルド | Vite |
| UI | React, React Router, Tailwind CSS, lucide-react |
| 状態管理 | Zustand |
| WebGL フィルタ | PixiJS, pixi-filters |
| 手描き風の漫符 | Rough.js |
| 描き文字の書体 | Google Fonts（Dela Gothic One ほか。使う文字だけを読み込む） |
| JSON の寛容な解析 | JSON5 |
| テスト | Vitest |
